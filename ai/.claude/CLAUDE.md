# 我的AI助手偏好

## 关于我
我是一名工作十年的程序员,熟悉C language/C++/java/python/shell等其他语言.  
不需要解释基础概念,直接给出专业级方案.  

## 编码要求
1.在开始编码前,请和我讨论清楚方案的目的和实现细节,除非用户要求立即实施,禁止直接开始编码.  
2.在设计编码方案时,请优先考虑方案的可行性:  
  - 方案引用的开源组件必须事实存在.  
  - 方案具备可测试性.  

3.关键代码必须有准确详细的注释.如果涉及到公式,需以典型场景的数字示例计算过程.禁止复述代码的注释.  
4.可读性优先于微观性能优化,优先于语法糖,但不得以可读性为由牺牲正确性.  
5.注释中的标点符号全部使用英文半角.  

### c language
1.基于C11进行编码,语法尽量向前兼容C99.  
2.代码注释使用//,且//和代码之间要有一个空格.如果当代码行不超过120列,则注释放在代码右侧.如果超过则注释位于代码上一行.  

### python
1.运行时基线 Python 3.11+(目标 3.13);不使用 3.13 独有语法,除非项目已锁定该版本.  
2.在代码简洁的基础上优先使用官方的库.  
3.单一功能脚本的代码需具备单文件调试功能(__main__).  
4.可执行入口(__main__)启动时必须先初始化日志:时间戳文件名,INFO 级别,同时输出到文件与终端;作为库被 import 时不得调用 logging.basicConfig().  

### java
1.基于java 8进行编码,确保语法向前兼容.  

## 更新文档
1.在每一次更新文档前重新读取文件(不需要保存在上下文),仅确保基于文档的最新版本修改.  
2.使用中文沟通和更新文档,标点符号使用英文半角.  
3.在我确认方案可行或提出新的要求后,更新项目的CLAUDE.md/AGENTS.md,在合适的章节完整的描述方案的实现步骤.  

## 我不希望 Claude 做的事
1.使用git保存任务执行过程中的阶段性成果,防止出现无法回退的情况.
2.禁止主动重构我没提到的代码
3.除非用户指定绝对路径的文件,禁止修改工作目录以外的目录和文件

## 安全要求
1.提交前必须确认没有凭据/大文件进入暂存区.  
2.rm -rf,git push --force,git reset --hard 等破坏性操作必须先确认.  
3.改动后必须给出可执行的验证命令.  
4.动态的内容放到配置文件中,配置文件名固定,`config.json`存放配置示例(脱敏数据),`config_local.json`存放真实配置(供用户填写,且程序优先读取,格式异常退出不降级).  
5.不得读取或输出任何凭据文件内容(*_local.json,.env,*.key,id_* 等).  
6.含真实凭据的配置文件必须加入 .gitignore,仓库内只提交脱敏示例.
